# Contributing to APIVerve

Thank you for your interest in contributing to APIVerve! 🎉

## Ways to Contribute

### 🐛 Report Bugs

Found a bug? Please [create an issue](https://github.com/apiverve/apis/issues/new) with:
- API name
- Request details (endpoint, parameters)
- Expected vs actual behavior
- Error messages or screenshots

### 💡 Request Features

Have an idea? We'd love to hear it!
- [Request a new API](https://github.com/apiverve/apis/issues/new?template=api_request.md)
- [Suggest a feature](https://github.com/apiverve/apis/issues/new?template=feature_request.md)

### 📚 Improve Documentation

See a typo or unclear documentation?
- Open a PR with your fix
- Or [create an issue](https://github.com/apiverve/apis/issues) describing the problem

### 🔧 Contribute Code

For SDK contributions:
1. Fork the repository
2. Create a feature branch (`git checkout -b feature/amazing-feature`)
3. Commit your changes (`git commit -m 'Add amazing feature'`)
4. Push to the branch (`git push origin feature/amazing-feature`)
5. Open a Pull Request

## Development Guidelines

### Code Style

- Follow the existing code style in each repository
- Use meaningful variable and function names
- Add comments for complex logic
- Include TypeScript types where applicable

### Testing

- Test your changes locally before submitting
- Include test cases for new features
- Ensure existing tests pass

### Commit Messages

Use clear, descriptive commit messages:
- `fix: resolve timeout issue in worldtime API`
- `feat: add support for XML response format`
- `docs: update authentication examples`

## Pull Request Process

1. Update documentation if needed
2. Follow the PR template
3. Link related issues
4. Wait for review (usually 1-3 days)
